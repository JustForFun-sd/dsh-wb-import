| # | 缺陷 | 严重度 |

## 逐条修复

### 缺陷 1：close 失败降级 + 半写入可回滚

**改法**：
```js
try {
  handle = await persistence.create(...);
  await handle.append(...);
  await handle.flush(...);
} catch (err) {
  if (created && !isAlreadyExists) {
    manifest.push({ ..., partial: true });   // 记录残留，供回滚
  }
} finally {
  if (handle) {
    try { await handle.close(); }
    catch (closeErr) { /* 降级为警告，不覆盖成功 */ }
  }
}
```

**验证**：
- ✅ close 失败时仍报告 `Imported 1 / 1`（不再谎报失败）
- ✅ close 失败降级为 `⚠ close 失败` 警告行
- ✅ append 失败标记 `[PARTIAL]`，写入台账供回滚

### 缺陷 2：删除 process.cwd() 兜底

**改法**：`workspaceDir` 改为**必填**，且必须是绝对路径（盘符/UNC/POSIX）。
拿不到合法路径就**拒绝导入**，绝不回退。

**验证**：
- ✅ `undefined` / `""` / `relative/path` / `DSH\零星工作` 全部被拒绝
- ✅ `D:/...`（正斜杠）和 `\\server\share`（UNC）被接受
- ✅ 代码里 0 处 `process.cwd()` 赋值

### 缺陷 3：严格参数校验

**改法**：新增 `strictInt()`，非法值直接抛错：
```js
function strictInt(value, label, { min, max, fallback }) {
  if (value === undefined) return fallback;
  if (typeof value !== 'number' || !Number.isInteger(value))
    throw new Error(`${label} must be an integer; got ...`);
  if (min !== undefined && value < min) throw ...
  if (max !== undefined && value > max) throw ...
  return value;
}
```

**验证**：`limit=1.5` / `"abc"` / `0` / `999`、`minBytes="abc"` / `-1` 全部抛错拒绝。

### 缺陷 4：去重

**改法**：`const ids = [...new Set(rawIds.map(x => x.trim()))]`

**验证**：重复 id 只 `create` 一次；报告为 `Imported 1 / 1`。

### 缺陷 5：不再依赖 exec.session

**改法**：`workspaceDir` 必填（见缺陷 2），彻底绕开 `exec.session` 的猜测。
从宿主源码确认 `exec` 的真实形状是 `{ agent, signal }`，`agent.session.header.cwd` 才是正确路径——
但因为改成必填参数，不再需要这条不确定的链。

**验证**：代码里 0 处 `exec?.session`。

### 缺陷 6：列表不再全量解析

**改法**：
- 新增 `scanFiles()`：只做目录遍历 + `stat`，不读内容
- 新增 `metaFor()` 缓存：按 `路径+mtime+size` 缓存标题，FIFO 淘汰
- 新增 `readHead()`：只读文件头 512KB 拿标题，不读整个 58MB 文件

**验证**：
- ✅ `wb_list_sessions` 耗时从全量扫描降到 **59–92ms**
- ✅ 仍能正确返回 144 个会话
- ✅ keyword 过滤时也只读命中的文件头

### 缺陷 7（新增）：备份与回滚

**改法**：
1. **导入台账**：每次导入写入 `$DSH_HOME/wb-import-ledger.json`（原子写入）
2. **新工具 `wb_rollback_import`**：
   - 无 `confirm=true` → **只报告不删除**
   - 只删台账里记录的、且名字以 `session-wb-` 开头的
   - 5 道安全护栏：前缀检查 → cwd 绝对路径 → `..` 检查 → 工作区编码合理性 → 父目录匹配
   - 删除后从台账移除条目

**验证**（11 项全过）：
- ✅ 空台账时明确告知
- ✅ 导入后台账被正确记录
- ✅ 未 confirm 时只报告不删除
- ✅ **伪造台账混入原生会话 → 拒绝删除**（`不是本插件创建的会话`）
- ✅ **伪造 `D:\..\..\Windows` → 拒绝删除**（`工作区编码异常`）
- ✅ 正常回滚：目录确实被删、台账条目被移除

## 仍然存在的已知限制（诚实说明）

1. **导入前不自动备份 `~/.dsh`**。台账只记录"我导入了什么"，不是完整快照。
   如果你要更强的保险，导入前应手动备份 `~/.dsh/sessions` + `session_projcache`。
   这个我没做——因为自动备份会写大量数据，需要你先确认策略。

2. **`close` 失败后写租约可能未释放**。已降级为警告，但会话文件可能处于
   "可读但租约残留"状态，需要重启 DSH 清理。

3. **thinking 降级问题依旧**。用非原模型续聊时 DSH 会把历史 thinking 当正文重放，
   这是 DSH 自身行为，插件层面无法解决。

4. **回滚只删文件目录，不动索引**。索引会在 DSH 重启后自动重建，
   但重启前侧边栏可能仍显示已删的会话。
